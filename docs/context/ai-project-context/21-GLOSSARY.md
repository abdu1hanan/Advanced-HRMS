# BeetleOps HRMS — Project Knowledge Pack
## 21-GLOSSARY.md: Domain Terminology, Acronyms & Status Dictionary

---

### 1. Project Terminology

- **Admin-Marked Leave**: A leave request granted directly by a Super Administrator without following the standard line-manager approval chain (`is_admin_marked = true`). Subsequent change requests on admin-marked leaves do not restart the manager chain.
- **Approval Chain Progress**: An integer (`approval_chain_progress`) indicating how many managerial levels in the boss chain have approved a leave request (e.g., Level 1, Level 2).
- **Approval Chain Target**: An integer (`approval_chain_target`) snapshotted from `SystemSetting::approvalLevels()` when a leave request is submitted, defining the number of manager approvals required before the request reaches the executive review stage.
- **Auto-Appended Sign-Out (Virtual Sign-Out)**: A synthetic `sign out` message generated by the system 1 minute after an employee's check-in when the employee signs in on a new calendar day without having closed their previous day's shift.
- **Boss Chain**: The ordered sequence of managers directly above an employee in the organizational hierarchy, returned as an array `[Level 1 Manager, Level 2 Director, ...]` by `HierarchyService::getBossChain()`.
- **Break Balance**: The official daily allowable break duration (configured to 3,600 seconds / 60 minutes).
- **Break Exceeded**: A state where an employee's cumulative breaks on a calendar day exceed the 75-minute limit (60m balance + 15m grace period). Subsequent break time is marked as unpaid time off.
- **Break Grace Period**: A hidden 900-second (15-minute) buffer added to the official 60-minute break balance before deductions or alerts kick in.
- **Guest Supervisor**: A user with `role: guest` who possesses line-management authority to review and approve subordinate leave requests, but is restricted from submitting personal leaves.
- **In-Flight Change Request**: An amendment submitted by an employee to modify the dates, leave type, or reason on an active or approved leave request. Forces an automated chain reset back to Level 1.
- **Leaf Node**: An employee in the organizational hierarchy who has no direct reports (`manager_id` is never set to their user ID).
- **Reconstruct Sessions**: The algorithmic process in `SessionManagementController` that reads raw Slack timestamps within a 24-hour lookahead window and pairs check-ins, breaks, and check-outs into daily work segments.
- **Retroactive Time Override**: A custom time modifier appended to a Slack message (e.g., `signin at 10:00 am`). Held in pending status until reviewed by a Super Administrator.
- **Special Order**: An integer column on the `users` table designating top executive positions: 1 = Chief Executive Officer (CEO), 2 = Chief Technology Officer (CTO), 3 = HR Manager.
- **Take Away**: The final net payable salary calculated as:
  $$\text{Take Away} = \max(0, (\text{Gross Salary} - \text{Total Deductions}) + \text{Sales Commission})$$
- **Track Record**: The consolidated monthly attendance and time-tracking sheet aggregating expected work hours, actual hours logged, break deductions, leaves, holidays, and net difference.

### 2. Status Dictionary

#### A. Leave Request Statuses (`leave_requests.status`)
| Status String | Definition |
|---|---|
| `pending` | Initial state upon submission; awaiting review by the next expected manager in the approval chain. |
| `approved_by_manager` | All required tiers in the manager chain have approved; awaiting final Super Admin sign-off. |
| `approved` | Fully approved by Super Admin; balance moved from `pending` to `used`. |
| `rejected_by_manager` | A line manager in the chain rejected the request. Chain stops unless reversed by that same manager. |
| `rejected` | Fully rejected by Super Admin; `pending` balance released. |
| `cancelled` | Cancelled by employee (instant if future) or approved for cancellation by Super Admin (if active/past). |

#### B. Slack Message Approval Statuses (`slack_messages.approval_status`)
| Status String | Definition |
|---|---|
| `null` | Standard real-time message without time modifier (e.g., `signin`). Active immediately. |
| `pending` | Message contains retroactive time modifier (e.g., `signin at 10 am`); awaiting Super Admin review. |
| `approved` | Super Admin approved the override; `override_at` becomes the active session timestamp. |
| `rejected` | Super Admin rejected the override; message is ignored during session reconstruction. |
| `pending_edit` | An approved message was edited by the employee in Slack; staged for Super Admin re-approval. |
| `merged` | Redundant or consolidated message merged into adjacent session segment. |

#### C. User Approval Statuses (`users.approval_status`)
| Status String | Definition |
|---|---|
| `pending` | Newly registered account; gated by `EnsureAccountApproved` middleware. |
| `approved` | Active employee account with full portal access. |
| `rejected` | Account rejected by Super Admin; portal access denied. |

### 3. Acronyms & Abbreviations

- **BFS**: Breadth-First Search (algorithm used for hierarchy tree construction and subordinate resolution).
- **DM**: Direct Message (Slack private messaging).
- **HMAC**: Hash-based Message Authentication Code (SHA-256 algorithm used for Slack webhook verification).
- **HRMS**: Human Resource Management System.
- **IDOR**: Insecure Direct Object Reference (security vulnerability category).
- **NLP**: Natural Language Processing (regex parsing of Slack attendance keywords).
- **RBAC**: Role-Based Access Control.
- **SA**: Super Administrator.
- **UTC**: Coordinated Universal Time (database storage timezone).
